    Dataset, decisões e status: página do projeto.

    Dataset, decisões e proposta aprovada estão na página do projeto e no EDA — não repetidos aqui. Resumo rápido: Stroke Prediction Dataset (Kaggle), tarefa de classificação binária (alvo stroke), ~4,87% de casos positivos.

    0. Ponto de partida

    O pipeline é o pipeline.py do EDA, importado (não copiado) em code/data.py, junto com a correção de outliers (cap_outliers) apontada lá — ambos ajustados só no treino. Mesmo split 80/20 estratificado do EDA (semente 42); a validação sai de um segundo split 80/20 estratificado dentro do treino, mesma semente: 3.270 treino / 818 validação / 1.022 teste.

    Definidos antes de treinar qualquer rede:

    • Métrica principal: PR-AUC (average precision). Escolhida em vez de ROC-AUC porque, com só ~4,9% de positivos, a ROC-AUC fica otimista (o eixo de falsos positivos é dominado pela classe majoritária); PR-AUC é sensível à raridade da classe positiva.
    • Critério de sucesso: PR-AUC da rede, no teste, ≥ 1,20× a PR-AUC do melhor baseline (também no teste).

    """Dados da entrega de Classificação — reaproveita o pipeline do EDA sem alterações.

Mesmo dataset, mesma tarefa e mesmo split treino/teste do EDA (semente 42). A
validação sai de dentro do treino do EDA (mais um split 80/20 estratificado,
mesma semente).
"""

import sys
from pathlib import Path

import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split

HERE = Path(__file__).resolve().parent
EDA_CODE = HERE.parents[2] / "projects" / "eda" / "code"
sys.path.insert(0, str(EDA_CODE))
from pipeline import CATEGORICAL_FEATURES, NUMERIC_FEATURES, TARGET, build_preprocessor  # noqa: E402
from eda import cap_outliers  # noqa: E402  (mesma correção de outliers apontada no EDA)

DATA_PATH = HERE / "data" / "healthcare-dataset-stroke-data.csv"


def load_splits():
    """Devolve (X_train, X_val, X_test, y_train, y_val, y_test, feature_names, preprocessor)."""
    df = pd.read_csv(DATA_PATH)

    # Mesmo split treino/teste do EDA (80/20 estratificado, semente 42).
    train_df, test_df = train_test_split(df, test_size=0.2, stratify=df[TARGET], random_state=42)
    # Validação sai de dentro do treino (80/20 estratificado, mesma semente).
    train_df, val_df = train_test_split(train_df, test_size=0.2, stratify=train_df[TARGET], random_state=42)

    # Correção do EDA: cap de outliers (IQR*1.5) em avg_glucose_level/bmi, ajustado só no treino.
    train_df, val_df, _ = cap_outliers(train_df, val_df, ["avg_glucose_level", "bmi"])
    train_df, test_df, _ = cap_outliers(train_df, test_df, ["avg_glucose_level", "bmi"])

    preprocessor = build_preprocessor()
    X_train = preprocessor.fit_transform(train_df).astype(np.float32)
    X_val = preprocessor.transform(val_df).astype(np.float32)
    X_test = preprocessor.transform(test_df).astype(np.float32)
    feature_names = list(preprocessor.get_feature_names_out())

    y_train = train_df[TARGET].to_numpy(dtype=np.float32)
    y_val = val_df[TARGET].to_numpy(dtype=np.float32)
    y_test = test_df[TARGET].to_numpy(dtype=np.float32)

    return {
        "X_train": X_train, "X_val": X_val, "X_test": X_test,
        "y_train": y_train, "y_val": y_val, "y_test": y_test,
        "feature_names": feature_names,
        "train_df": train_df, "val_df": val_df, "test_df": test_df,
    }

    2. A rede

    MLP em PyTorch, 1 logit de saída (BCEWithLogitsLoss com pos_weight = 19,566 — a razão negativos/positivos do treino, já que o enunciado deste projeto pede tratar o desbalanceamento na perda). Arquitetura de partida: 23 → 32 → 16 → 1 (ReLU nas ocultas) — 1.313 parâmetros contra 3.270 linhas de treino (≈ 2,5 linhas por parâmetro): rede pequena de propósito, dado o tamanho do treino e o risco de overfitting já visto no EDA (dataset de 5 mil linhas).

    """MLP binária em PyTorch, com parada antecipada — reutilizada em toda a Etapa 4/5.

Saída de 1 logit (BCEWithLogitsLoss, com pos_weight para o desbalanceamento).
Regularização opcional: weight decay (no otimizador) e dropout (na rede).
"""

from pathlib import Path

import numpy as np
import torch
import torch.nn as nn


class MLP(nn.Module):
    def __init__(self, n_features: int, hidden: list[int], dropout: float = 0.0,
                 batchnorm: bool = False):
        super().__init__()
        layers = []
        in_dim = n_features
        for h in hidden:
            layers.append(nn.Linear(in_dim, h))
            if batchnorm:
                layers.append(nn.BatchNorm1d(h))
            layers.append(nn.ReLU())
            if dropout > 0:
                layers.append(nn.Dropout(dropout))
            in_dim = h
        layers.append(nn.Linear(in_dim, 1))
        self.net = nn.Sequential(*layers)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        return self.net(x).squeeze(-1)  # logit


def n_params(model: nn.Module) -> int:
    return sum(p.numel() for p in model.parameters())


def train_with_early_stopping(
    model: nn.Module, X_train, y_train, X_val, y_val, *, lr: float, weight_decay: float = 0.0,
    batch_size: int = 64, max_epochs: int = 300, patience: int = 20, pos_weight: float | None = None,
    checkpoint_path: Path | None = None, seed: int = 42,
) -> dict:
    torch.manual_seed(seed)
    Xt = torch.from_numpy(X_train)
    yt = torch.from_numpy(y_train)
    Xv = torch.from_numpy(X_val)
    yv = torch.from_numpy(y_val)

    pw = torch.tensor(pos_weight, dtype=torch.float32) if pos_weight is not None else None
    loss_fn = nn.BCEWithLogitsLoss(pos_weight=pw)
    optimizer = torch.optim.Adam(model.parameters(), lr=lr, weight_decay=weight_decay)

    n = Xt.shape[0]
    checkpoint_path = checkpoint_path or Path("best.pt")

    best, wait = float("inf"), 0
    history = {"train_loss": [], "val_loss": []}
    rng = np.random.default_rng(seed)

    for epoch in range(max_epochs):
        model.train()
        perm = rng.permutation(n)
        epoch_loss = 0.0
        for start in range(0, n, batch_size):
            idx = perm[start:start + batch_size]
            xb, yb = Xt[idx], yt[idx]
            optimizer.zero_grad()
            loss = loss_fn(model(xb), yb)
            loss.backward()
            optimizer.step()
            epoch_loss += loss.item() * len(idx)
        train_loss = epoch_loss / n

        model.eval()
        with torch.no_grad():
            val_loss = loss_fn(model(Xv), yv).item()

        history["train_loss"].append(train_loss)
        history["val_loss"].append(val_loss)

        if val_loss < best:
            best, wait = val_loss, 0
            torch.save(model.state_dict(), checkpoint_path)
        else:
            wait += 1
            if wait >= patience:
                break

    model.load_state_dict(torch.load(checkpoint_path))
    history["stopped_epoch"] = epoch + 1
    return history


def predict_proba(model: nn.Module, X) -> np.ndarray:
    model.eval()
    with torch.no_grad():
        logits = model(torch.from_numpy(X))
        return torch.sigmoid(logits).numpy()

    3. Treinamento

    Adam, lr = 1e-3, lotes de 64, até 300 épocas, parada antecipada com paciência de 20 épocas pela perda de validação, restaurando os melhores pesos (checkpoint) — exatamente o esqueleto do enunciado. A rede base parou na época 39 (perda de treino final 0,7519, validação 0,9480).

    Figuras

    A curva de treino continua caindo depois da época ~10, enquanto a de validação estabiliza e começa a subir — o clássico sinal de overfitting a partir daí; a parada antecipada evita continuar treinando sobre esse ponto.

    5. Avaliação no teste

    A configuração escolhida foi retreinada do zero em 3 sementes (42, 43, 44); o teste só foi usado uma vez por semente, depois de toda decisão de hiperparâmetro já fechada pela validação. O limiar de decisão foi escolhido por semente, maximizando o F1 da classe positiva na validação — priorizando não deixar passar casos de AVC em vez de maximizar acurácia simples (o custo de um falso negativo aqui é clinicamente maior que o de um falso positivo).

    Semente Limiar PR-AUC (teste) ROC-AUC (teste) F1-macro (teste)
    42 0,651 0,2612 0,8432 0,5664
    43 0,704 0,2619 0,8398 0,6071
    44 0,733 0,2580 0,8415 0,5972

    PR-AUC no teste (média ± desvio, 3 sementes): 0,2604 ± 0,0017.

    Modelo PR-AUC (teste)
    Dummy (trivial) 0,0489
    Logística (linear) 0,2756
    MLP (média de 3 sementes) 0,2604 ± 0,0017

    Critério de sucesso (Etapa 0) atingido? Não. 0,2604 < 1,20 × 0,2756 = 0,3308 — a MLP nem sequer superou a regressão logística nesta tarefa (0,2604 contra 0,2756), quanto mais bater 20% acima dela. A diferença entre os dois (0,0152) é quase 9× maior que o desvio entre sementes (0,0017), e a direção é consistente nas 3 sementes: a logística ganha da MLP em todas.

    Com esse limiar, a rede detecta 39 dos 50 casos reais de AVC no teste (recall de 78% na classe positiva), ao custo de 211 falsos alarmes — uma troca deliberada: o limiar foi escolhido para não perder casos positivos, não para acertar tudo.

    6. Análise de erros

    Taxa de erro por subgrupo (teste, seed 42):

    Subgrupo Taxa de erro n
    hypertension = 0 17,16% 921
    hypertension = 1 63,37% 101
    heart_disease = 0 20,06% 967
    heart_disease = 1 50,91% 55

    O erro é muito maior exatamente nos subgrupos de maior risco (hypertension = 1, heart_disease = 1) — mas não porque o modelo erra o AVC neles; é o oposto: como a matriz de confusão é dominada por falsos positivos (211 contra só 11 falsos negativos), a maior parte do "erro" nesses subgrupos é a rede marcar como risco de AVC pacientes hipertensos/cardiopatas que, neste teste específico, não tiveram o evento — o modelo aprendeu corretamente que esses fatores elevam o risco (consistente com a Figura 5 do EDA) e por isso fica mais "nervoso" com esses pacientes, errando para o lado conservador.

    5 piores exemplos (maior |probabilidade − rótulo|):

    idx y prob age hypertension heart_disease
    553 1 0,0124 14 0 0
    165 1 0,0654 45 0 0
    686 1 0,0863 42 0 0
    436 0 0,8756 81 1 1
    240 1 0,1254 32 0 0

    Quatro dos cinco piores erros são falsos negativos em pacientes jovens sem hipertensão nem doença cardíaca (14, 45, 42 e 32 anos) — casos de AVC que a rede não tinha nenhum sinal de risco "clássico" para prever, já que idade é o fator dominante (ver importância por permutação abaixo) e esses pacientes são justamente os que a rede, corretamente segundo os dados, julgaria de baixo risco. O quinto (idx 436) é o oposto: 81 anos, hipertenso e cardiopata — um paciente que "deveria" ter tido o evento segundo o perfil de risco, mas não teve.

    age domina isoladamente (queda de PR-AUC de 0,1839, mais de 6× a segunda colocada) — bate exatamente com o EDA, onde age já era a numérica mais correlacionada com o alvo (Spearman 0,25) e a mais separada no boxplot por classe (Figura 6 do EDA). Em seguida vêm hypertension/heart_disease (quedas de ~0,027/0,026), também consistentes com a Figura 5 do EDA (maior taxa de AVC nesses grupos). A rede não "descobriu" nenhum fator de risco que o EDA não tivesse apontado — ela aprendeu, com outra ferramenta, os mesmos sinais que a análise exploratória já tinha revelado.

    7. Conclusão

    A rede valeu a pena? Não, pelo critério definido na Etapa 0 — e esse é o resultado honesto a reportar, não um erro de implementação: a regressão logística (um baseline linear) teve PR-AUC de teste igual ou melhor que a MLP nas 3 sementes. Com só 3.270 linhas de treino, 23 features (a maioria binárias de one-hot) e um sinal dominado por uma única feature contínua (age) de relação aproximadamente monotônica com o alvo, o problema tem pouca estrutura não linear para uma rede explorar — exatamente o tipo de cenário em que um modelo linear simples compete de igual para igual com uma MLP.

    Limitações: o dataset é pequeno para o padrão de redes neurais e extremamente desbalanceado (50 casos positivos no teste inteiro) — qualquer métrica no teste tem alta variância amostral (um único caso a mais ou a menos muda a PR-AUC de forma visível). Quem seria afetado por um erro: um falso negativo aqui é um paciente de risco real de AVC classificado como baixo risco — o custo mais grave dos dois tipos de erro, e a escolha de limiar da Etapa 5 já reflete isso (prioriza recall). Com mais tempo: valeria tentar reamostragem (SMOTE) em vez de só pos_weight, e um modelo de árvores (random forest/boosting) como segundo baseline — o enunciado já avisa que eles costumam empatar com a rede em dados tabulares, e aqui a suspeita é que também empatariam ou ganhariam.

    Bônus de competição: não se aplica — o Stroke Prediction Dataset é uma página de dataset do Kaggle, não uma competição aberta com submissão e leaderboard (ao contrário de, por exemplo, Titanic/Spaceship Titanic), então não há como gerar a submissão que o bônus pede.
